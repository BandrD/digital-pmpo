# Замена Telegram → MAX

Бизнес-логика (PostgreSQL, вопросы, расписание, LLM) остаётся. Вместо aiogram стоит слой `bot/max_platform`: long polling `GET /updates` и запросы на `https://platform-api2.max.ru`.

Токен: `MAX_BOT_TOKEN`. Админы: `ADMINS_MAX_IDS`. Переменные `BOT_TOKEN`, `ADMINS_TG_IDS`, `ERROR_LOG_TOPIC_ID` и `WEEKLY_TOKEN_REPORT_TOPIC_ID` больше не читаются.

| Как сделано в Telegram | На что меняется в MAX | Статус |
|---|---|---|
| aiogram `Bot` + `dp.start_polling` | `bot/max_platform`: `GET /updates`, заголовок `Authorization` без `Bearer` | выполнено |
| `api.telegram.org` | `https://platform-api2.max.ru` | выполнено |
| Проверка TLS обычными CA | Корень Минцифры: `bot/certs/russian_trusted_root_ca.pem`, в Docker он добавляется в системное хранилище. Проверка сертификата не отключается | выполнено |
| Webhook Telegram | Не делался. Бот как и раньше на long polling. Webhook MAX (`POST /subscriptions`, только HTTPS 443) | не выполнено |
| `InlineKeyboardButton(callback_data=...)` | Вложение `inline_keyboard`, кнопка `callback`, поле `payload` | выполнено |
| `InlineKeyboardButton(url=...)` | Кнопка `link` | выполнено |
| `callback.answer()` / `show_alert=True` | `POST /answers`. `show_alert` не отличается от обычного ответа: в MAX это одноразовый тост `notification` | выполнено |
| Лимит ответов на кнопки | Пауза, чтобы не чаще 2 ответов в секунду на чат | выполнено |
| `edit_message_text` | `PUT /messages?message_id=`. id сообщения — строка `mid`, не число Telegram | выполнено |
| `send_message` / `message.answer` | `POST /messages`. Личный ответ уходит в `chat_id` диалога. Рассылка сотруднику — параметром `user_id`, в чат команды — `chat_id` | выполнено |
| `ReplyKeyboardRemove` | Ничего не отправляет: постоянной клавиатуры под полем ввода в MAX нет | выполнено |
| `parse_mode=HTML` | `format: "html"`. Теги `<b>`, `<i>`, `<code>`, `<a>`, `<blockquote>` остаются | выполнено |
| Списки, таблицы, `<hr>` в тексте | В MAX не рисуются. В текстах бота списки уже идут строками с «•» | выполнено |
| Многострочный `<pre>` | В MAX переводы строк внутри блока схлопываются в пробелы | не выполнено |
| `/start`, `/show_id`, `/create_command` как текст | Тот же разбор текста сообщения | выполнено |

| Deep link `https://t.me/<bot>?start=<code>` | `https://max.ru/<username>?start=<code>`. Событие `bot_started` превращается в сообщение `/start <payload>`. Код приглашения `token_urlsafe(16)` короче лимита 128 символов | выполнено |
| FSM aiogram, `MemoryStorage` | Свой `MemoryStorage` в памяти процесса, те же классы состояний | выполнено |
| Голос: `message.voice.file_id` и скачивание с `api.telegram.org` | Вложение `audio`. Если в нём есть `transcription`, берём её. Если нет — скачиваем `url` и по-прежнему гоняем через ffmpeg и Vosk. `getFile` нет | выполнено |
| Голос и клавиатура в одном сообщении | Не отправляем: у MAX `audio` не сочетается с клавиатурой. Подтверждение распознавания и раньше уходило отдельным сообщением | выполнено |
| `send_photo` / `answer_photo` | Загрузка `POST /uploads?type=image`, затем вложение `image`. Повтор, если API ответит `attachment.not.ready` | выполнено |

| `message.delete()` | `DELETE /messages`. Если MAX не даст удалить чужое сообщение, ошибка глотается, как и раньше | выполнено |
| APScheduler, утро / вечер / отчёт | Без изменений. У MAX нет `send_at`, свой планировщик как раз нужен | выполнено |

| Лог ошибок в чат Telegram (`sendMessage`) | `ERROR_LOG_CHAT_ID` — id чата MAX. `ERROR_LOG_TOPIC_ID` удалён | выполнено |
| Фильтр «только личка» / «только группа» | `dialog` → `private`, `chat` → `group`, `channel` по-прежнему отсекается | выполнено |
| Лимит текста 3950, у Telegram 4096 | Режущая проверка в коде бота прежняя. Дополнительно слой отправки режет сырой текст по 4000 символов | выполнено |
| Маркер long polling | Хранится только в памяти. После рестарта чтение идёт с текущего хвоста, пропущенное за простой не догоняется | не выполнено |

| Переименование колонок `tg_id`, удаление `chat_topic_id` | Схема базы не менялась | не выполнено |

## Неординарные случаи

**Личное сообщение и чат команды.** В Telegram в личке `chat_id` совпадал с id пользователя, а группа опознавалась по минусу. В MAX оба id положительные и разные. Ответ на входящее сообщение уходит в `chat_id` этого апдейта. Сообщение сотруднику из планировщика уходит параметром `user_id`. Если id есть в `teams.chat_id` или бот уже видел этот чат как группу (`bot_added` / сообщение с `chat_type=chat`), уходит параметром `chat_id`.

**Старт по ссылке.** Отдельной команды в апдейте нет: приходит `bot_started` с `payload`. Слой сам собирает текст `/start <payload>`, чтобы регистрация по приглашению не переписывалась.

**Голос.** Платформа может прислать уже готовый текст в `transcription`. Пока поля нет, файл качается по `url` и распознаётся локально. Формат контейнера может быть не OGG: ffmpeg по-прежнему приводит его к WAV 16 кГц.

**Топики.** Отчёты, которые раньше попадали в тему супергруппы, теперь попадают в общий чат. Если команде нужна изоляция, это отдельный чат, а не тема.

**Правка сообщения по кнопке.** `message_id` — строка `mid`. В `PUT` нельзя передать `disable_link_preview` (в Telegram это был `disable_web_page_preview` в теле). Для новой отправки флаг уходит query-параметром `disable_link_preview`.

**Удаление сообщения пользователя** в сценарии ТЗ. Запрос уходит, но бот может не иметь права удалять чужие сообщения. Ошибка по-прежнему не останавливает сценарий.
